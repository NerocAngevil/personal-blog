堆排序：从二叉堆到原地排序

2026 年 5 月 5 日 · 胡逸枫 · 算法

引言

排序是计算机科学中最基础的问题之一。在众多基于比较的排序算法中，堆排序（Heap Sort）以其 $O(n \log n)$ 的最坏时间复杂度和 $O(1)$ 的额外空间开销，占据了独特的位置。它不像快速排序那样依赖随机化来避免最坏情况，也不像归并排序那样需要额外的线性空间。

理解堆排序的关键在于理解一种精巧的数据结构——二叉堆。本文将从堆的定义与性质出发，逐步推导堆排序的完整过程。

二叉堆

定义

二叉堆是一棵完全二叉树，同时满足堆序性质。以最大堆（max-heap）为例，堆序性质要求每个节点的值都大于或等于其所有子节点的值：

$$A[\text{parent}(i)] \geq A[i]$$

相应地，最小堆（min-heap）要求 $A[\text{parent}(i)] \leq A[i]$。堆排序通常使用最大堆来实现升序排序。

数组表示

由于完全二叉树的特殊结构，二叉堆可以非常高效地用数组表示，而不需要使用指针。对于下标从 $0$ 开始的数组，下标为 $i$ 的节点满足：

  • 父节点：$\lfloor (i-1)/2 \rfloor$
  • 左子节点：$2i + 1$
  • 右子节点：$2i + 2$

这种表示使得我们可以在 $O(1)$ 时间内找到任意节点的父节点或子节点，且不需要额外指针存储——这正是堆排序能够原地工作的基础。

核心操作：下沉（Sift-Down）

堆排序中最核心的操作是下沉：当一个节点的值可能小于其子节点时，将该节点与较大的子节点交换，然后递归地对新位置执行同样的操作，直到堆序性质恢复。这个操作也常被称为 heapify 或 percolate-down。 

def sift_down(arr, n, i):
    """将 arr[i] 在大小为 n 的堆中下沉，恢复最大堆性质"""
    largest = i
    left = 2 * i + 1
    right = 2 * i + 2

    if left < n and arr[left] > arr[largest]:
        largest = left
    if right < n and arr[right] > arr[largest]:
        largest = right

    if largest != i:
        arr[i], arr[largest] = arr[largest], arr[i]
        sift_down(arr, n, largest)

下沉操作的时间复杂度为 $O(\log n)$，因为在最坏情况下，节点需要一直下沉到叶子节点，路径长度等于树的高度。

建堆

有了下沉操作之后，建堆变得非常简洁。高效的做法是从最后一个非叶子节点开始，自底向上地对每个节点执行下沉操作。

最后一个非叶子节点的下标为 $\lfloor n/2 \rfloor - 1$。从这个节点开始向前遍历到根节点，对每个节点调用 sift_down。 
def build_heap(arr):
    n = len(arr)
    for i in range(n // 2 - 1, -1, -1):
        sift_down(arr, n, i)

建堆复杂度分析

这个过程的复杂度分析非常有趣。虽然每次下沉是 $O(\log n)$，但不同高度的节点数量不同——大部分节点靠近叶子，下沉代价很小。令 $h$ 表示节点的高度，高度为 $h$ 的节点最多有 $\lceil n/2^{h+1} \rceil$ 个，每个代价为 $O(h)$，因此总时间为：

$$\sum_{h=0}^{\lfloor \log n \rfloor} \frac{n}{2^{h+1}} \cdot O(h) = O(n) \cdot \sum_{h=0}^{\infty} \frac{h}{2^{h}} = O(n)$$

最后一步用到了无穷级数 $\sum_{h=0}^{\infty} h/2^h = 2$ 的性质。因此，建堆是线性时间 $O(n)$ 的，而非直观猜测的 $O(n \log n)$。

排序过程

建堆完成后，数组被组织成了一个最大堆——根节点（下标 $0$）是最大的元素。排序的思路非常巧妙：

  1. 将堆顶（最大值）与堆的最后一个元素交换
  2. 将堆的大小减少 $1$（最后一个元素已就位）
  3. 对新的堆顶执行下沉操作，恢复堆序性质
  4. 重复以上步骤，直到堆的大小为 $1$
def heap_sort(arr):
    n = len(arr)
    build_heap(arr)
    for i in range(n - 1, 0, -1):
        arr[0], arr[i] = arr[i], arr[0]  # 交换堆顶与末尾
        sift_down(arr, i, 0)             # 在缩小的堆中恢复堆序

这个过程对每个元素执行一次 $O(\log n)$ 的下沉，因此排序阶段的时间复杂度为 $O(n \log n)$。

完整实现

以下是堆排序的完整 Python 实现，合并了建堆与排序两个阶段：

def heap_sort(arr):
    """堆排序，升序排列，原地排序 O(1) 额外空间"""
    n = len(arr)

    # 建堆：自底向上
    for i in range(n // 2 - 1, -1, -1):
        _sift_down(arr, n, i)

    # 逐个提取最大值
    for i in range(n - 1, 0, -1):
        arr[0], arr[i] = arr[i], arr[0]
        _sift_down(arr, i, 0)


def _sift_down(arr, n, i):
    """将 arr[i] 下沉到合适位置（迭代版本）"""
    while True:
        largest = i
        left = 2 * i + 1
        right = 2 * i + 2
        if left < n and arr[left] > arr[largest]:
            largest = left
        if right < n and arr[right] > arr[largest]:
            largest = right
        if largest == i:
            break
        arr[i], arr[largest] = arr[largest], arr[i]
        i = largest

与其他排序算法的比较

  • vs 快速排序：快速排序在实践中通常更快（更好的缓存局部性），但最坏情况下退化为 $O(n^2)$。堆排序保证了 $O(n \log n)$ 的严格上界，在对最坏情况敏感的场合更可靠。
  • vs 归并排序：归并排序是稳定的排序算法且同样保证 $O(n \log n)$，但需要 $O(n)$ 额外空间。堆排序是原地算法，适合内存受限的场景。
  • vs 插入排序：对于小规模数据或接近有序的数据，插入排序更快。实际应用中常将堆排序与插入排序混合使用（如 IntroSort）。

优先队列视角

堆排序可以理解为：将所有元素插入一个优先队列（最大堆），然后反复取出最大值。这种视角揭示了堆排序与优先队列之间的本质联系——实际上，二叉堆正是实现优先队列的标准数据结构。

在这个框架下，建堆等同于 $n$ 个元素的批量入队，排序等同于 $n$ 次出队操作。理解了优先队列，也就理解了堆排序。

总结

堆排序的美妙之处在于，它利用完全二叉树在数组中的紧凑表示，在不使用额外空间的前提下，达到了 $O(n \log n)$ 的比较排序下界。它的核心思想——建堆和反复提取堆顶——简单而深刻。

理解堆排序不仅是学习排序算法的重要一环，更是理解堆这种数据结构及其在优先队列、图算法（如 Dijkstra 最短路径算法、Prim 最小生成树算法）中广泛应用的基础。
